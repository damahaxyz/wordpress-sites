# Group Shop Manager 接手约定

先读 README.md、docs/HANDOFF.md、docs/ARCHITECTURE.md、CHANGELOG.md，再修改实现。每次功能、权限、配置、限制、兼容性或部署变化，必须在同一轮更新对应文档、CHANGELOG 和 HANDOFF。记录实际验证与上线状态，不将计划写成完成。不能只改代码而遗漏注意事项。

顾客每店独立原生用户，可在不同店复用可见用户名和真实邮箱；密码、默认地址和会话独立。Administrator／Shop Manager 为独立共享员工身份，由网络超级管理员按店授权，无自动 SSO。顾客角色固定 Customer，不能转换为员工。各店商品/评论/订单独立。0.3.1 按最新用户决定使用主站原生产品分类／标签作为唯一权威，全店投影只读；主商品归属同步到关联版本。覆盖 0.3.0 独立分类决定，不恢复旧模板/覆盖 UI。集合仍按店独立。库存按用户最新决定全部关闭管理、始终有货，不能恢复旧版零库存和批量库存入口；商品发布状态独立。支付与自动 SSO 尚未开发。WooCommerce CRUD / HPOS、跨店 finally 恢复、网络管理员权限与 nonce、只读代码挂载都必须保留。禁止将密码、邮件正文、地址或凭据写入日志/文档。卸载默认保留业务数据。

继承项目根目录 AGENTS.md。**最新用户要求只在本地测试，未收到新的明确发布通知前不得部署到 contabo2 或执行线上分类清理。** 生产操作以后仍须先读 docs/OPERATIONS.md。独立 QA 的 synthetic 集成测试不能运行到生产，生产验收脚本只用于本次已明确授权的测试数据安装。

后续重构优先原生后台扩展，聚焦按店归属的差异数据与主题读取，避免再写商品/订单/分类/评论/用户基础编辑器。先读 docs/NATIVE-ADMIN-REFACTOR.md；整体重构仍是规划，0.2.1 仅先做店铺 Logo 原生媒体选择和收录设置。跨店全部视图需查询/上下文适配，不能声称加一个筛选框即具有原生跨店处理能力。

0.3.1 店铺商品由 ProductAdmin 渲染；上下架用所属店原生状态，不能影响其他店版本。图片/富文本插入必须使用按店媒体授权。变体每页 20 个，保存前验证全部提交行、父子归属与价格，末尾完整标记防 PHP 截断；无效输入保留 120 秒私有草稿供修正，不写日志。分类只能通过主站原生入口管理，SharedTaxonomies 保留必要原生投影与来源映射，不能跨站直接复用数字 term/attachment ID。

0.3.2 集合为主要选品单元：列表与编辑分开，删除进入可恢复回收站，不能误删商品或共享分类；新集合内部 slug 自动生成，已有 slug／parent 保留但不开放编辑。选品 AJAX 必须网络管理员、按店 nonce、跨店 finally；不得只搜固定前 200 件。CollectionDisplay 的区块、短代码、主题接口与经典 Shop 筛选必须使用同一份本店派生关系，公开查询限制 publish／Woo 可见性，非法集合不能退回全部商品。Store API 独立查询区块不自动套用经典主查询筛选。

0.3.3 TaxonomyAdmin 只补原生类型／店铺范围和集合链接，不改变原生 CRUD 或权限；集合归属必须按当前店上下文判断，不能把主站原生列表解释成全网集合汇总。

0.3.4 移除统一订单页及聚合／详情／有限状态／备注写操作，概览使用所属店原生入口。必须在目标店判断 HPOS；保留来源、前台权限和已有 HPOS 来源列。无全网同屏查询或新 SSO。QA 已被外部改为独立域名，重跑 localhost 套件前确认隔离配置；不自动恢复用户域名设置。

- 0.3.5 本地：删除独立评论页及 review_status，原生产品 Reviews 仅增加只读所属店铺列（店名＋当前 blog_id），评论和回复均支持；不聚合、迁移或共享评论，不加 commentmeta，不改原生权限及普通评论页。QA 当前已为 www.main.local 等 .local 域名，宿主 loopback，保留既有映射，不能使用旧 localhost 路径或公网同名站误验收。

- 0.3.6 本地：删除共享客户页，原生网络用户仅补只读首次来源店铺，复用 Sites 当前成员关系，不把历史 joined_at 当现成员；无用户迁移或新元数据。保留 Customers 登录、角色保护、共享地址、密码范围提示和会话撤销。来源读取必须同网络、恢复上下文且不可用时保留编号；新列不扩展各店用户页，不扩大权限。

- 0.3.7 本地：用户明确移除主商品发布标签及功能，跨店复制／覆盖／媒体导入／新发布映射 API 已删除，不得按旧规划移至原生面板或为测试恢复。保留本店编辑、上下架、已有商品／变体／附件／来源元数据／历史映射与审计，旧映射仅继续服务既有分类归属同步。无数据清理迁移；旧依赖 Catalog::publish 的 fixture 套件不可直接执行，当前退休验证使用 retired-publisher.php、catalog-state.php 和 check-retired-publisher-local.py。仍只本地，未获新通知不发布。

- 0.4.0 本地已实施用户隔离：Identities 维护原生用户的类型／店铺／可见用户名和邮箱索引，顾客真实邮箱仍写 wp_users；内部用户名唯一。Customers 覆盖登录、Cookie、重置、角色、REST 与注册；UserAdmin 复用原生网络用户创建员工及按店授权面板；IdentityPrivacy 适配原生按邮箱导出／擦除；UserMigration 只能显式运行，先备份与预检，绝不在访问页面／激活时自动拆分。既有本地共享顾客已拆分，订单／评论／购物车／下载／令牌按所属店重绑。旧全局 get_user_by(email) 有歧义，第三方集成须使用本店解析，不承诺任意插件自动兼容。回滚须成套数据库与源码；仍未获生产发布授权。历史 0.3.6 的共享行为及仅网络列限制已被本次决定覆盖。

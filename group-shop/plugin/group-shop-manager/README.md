# Group Shop Manager

本地源码 **0.5.9**：一套 WordPress／WooCommerce 商城，多个品牌门面。当前本地已关闭 Multisite 并迁移七个品牌；**未发布生产**。用户后续明确通知前不得部署。

当前入口：[商城后台](http://www.main.local/wp-admin/admin.php?page=group-shop-manager&gsm_brand=0)。品牌 A／B／C／E／F／G 分别为 www.branda.local、www.brandb.local、www.brandc.local、www.brande.local、www.brandf.local、www.brandg.local，均为本机 HTTP、80 端口。

先读 [接手状态](docs/HANDOFF.md)、[架构](docs/ARCHITECTURE.md)、[使用说明](docs/USER-GUIDE.md)、[运维与回滚](docs/OPERATIONS.md)、[变更记录](CHANGELOG.md)。根目录 PROJECT-HANDOFF.md 为复制来的 Trovesia 历史材料，不能当作当前规格。

## 0.5.9 公开资源与 SEO 隔离（2026-11-06，本地）

新增 SeoIsolation，补齐商品／变体按 ID 与 Store API slug 读取、页面／文章、评论及私有集合的公开访问边界。外店或公共商品 ID 返回404，不再猜测跳转到同名商品；有效本店旧 slug 仍沿用原生301。相同公开商品／页面路径在不同店铺解析为各自资源；路由同时约束资源类型。查询中的OR条件不能绕过品牌条件。

共享分类、标签与制造商品牌仍共用词条资料；各店的商品及评论计数独立，Store API与原生Woo REST（含内部子请求）不再返回全局数量。分类／属性聚合缓存显式带品牌范围，价格／库存／评分聚合继续使用受限原生商品查询。私有集合单条／列表／归档与显式include均校验归属。原生Sitemap分类只列本店有商品的分类及共享祖先，作者Sitemap关闭；产品、页面、文章Sitemap与Feed沿用受限原生查询。

菜单保持原有归属校验。正文／摘要／短描述中的外店业务锚点及iframe在渲染时移除href／src，外店oEmbed不解析；不修改保存的正文。canonical及旧slug跳转不得指向其他注册店铺。CSS、JS、图片与其他wp-content素材继续共用，不改变来源域名。

46项运行层与141次真实HTTP中的315项检查通过，覆盖A／B启用收录、Sitemap、canonical、JSON-LD、正文／菜单链接、搜索、Feed、ID／slug、分类统计、REST及七店商品链接；清理24条合成内容／商品／菜单项、7词条及3评论，原八张业务表与七品牌业务配置核对保留，仍72公共＋72品牌商品。详见qa/group-shop-manager/v059-local/LOCAL-v059.md。仅本地，未部署；第三方SEO插件、自定义SQL／接口及未来Woo升级须专项复验，不承诺任意插件自动隔离。

## 0.5.8 商品展示继承与店铺独立加购（本地）

保留 Trovesia add-ons，按店铺独立配置，不继承公共商品规则。公共商品的 add-ons 面板仅提示进入品牌版本配置；品牌版本的选择器只列同店其他简单商品及具体变体。保存前验证完整表单、原生编辑授权和同店关系，拒绝公共／跨店／自身关联；最多20条规则。原生元数据写入也校验归属，现有规则不自动复制或删除。

加购时核对规则与商品，子项不继续触发嵌套加购。购物车重算检查真实父行、规则、子商品及变体、所属店铺与可购买状态；规则删除、换绑或商品不可用时移除失效加购并提示重选，不再使用旧价格快照兜底。跟随价格／固定价／折扣继续可用，数量跟随主项；加购价不污染同一商品的普通购物车行。独立原生订单行、父项移除联动及普通迷你购物车数量按钮保持。

Product presentation 默认动态继承公共商品，涵盖Eyebrow、Key benefits、退货说明、配送说明、Order activity文案及原有配送天数元数据；公共修改即时生效，不向品牌批量复制文案。在该面板勾选“单独设置本店展示信息”后可独立编辑，取消勾选并保存恢复当前公共值。留空仍使用Trovesia原有默认文案；自动订单数的查询与缓存均按当前店铺计算，不继承另一店的数量。继承模式字段不可编辑，服务端忽略伪造字段并阻止直接元数据覆盖；覆盖选择沿用 `_gsm_overrides` 的presentation项。

Group Shop Manager 0.5.8、Trovesia Plugin 3.8.4；单店插件保留原有基本行为，多店规则由 ProductExperience 适配层施加。原生编辑和经典加购为当前支持入口，Store API购物车读取／变更已有项经过相同重算；不宣称新增区块加购选择器或第三方编辑器兼容。

本轮开始只读盘点为72公共＋72品牌版本，已有展示及加购元数据均为0；没有自动改写这些业务商品、建立版本或设置营销规则。29项运行、5项订单统计和23项真实HTTP检查，以及浏览器实际覆盖保存／恢复继承通过；合成资料清理与原商品／元数据／品牌设置快照核对见 `qa/group-shop-manager/v058-local/LOCAL-v058.md`。仅本地，未连接或发布生产。

## 原生菜单按店铺管理（0.5.7，本地）

外观 → 菜单新增“菜单所属店铺”切换，总管理员直接进入默认主店。每店可建立多个菜单，Primary／Footer 位置及自动添加页面设置独立。左侧商品、页面、文章只显示本站已发布资料；商品只使用品牌销售版本，排除公共档案。Product categories 包含共享分类与本站启用且未回收的集合，标签仍共用。自定义链接限本站域名、以 `/` 开头的相对路径或 `#` 锚点，不提供外部链接。

服务器在原生表单或 AJAX 写入前校验店铺签名、菜单／菜单项归属、资源与父项；阻止跨店资源、其他菜单的菜单项、循环层级和跨店位置绑定，非法混合保存不会先改菜单名。前台按域名读取位置，并过滤历史无效／跨店条目；不自动删除既有资料。页面自动添加在归属写入后按页面所属店铺执行。

品牌 Administrator 使用“店铺菜单”入口，只授予菜单页面和受控 AJAX 所需能力；不获得主题、插件或全局设置权限，Shop Manager 权限保持。经典原生编辑器是当前受支持入口，Customizer 菜单组件及菜单相关 REST 编辑入口关闭，第三方菜单编辑器需另行适配。WordPress 菜单名称仍全站唯一，建议使用“店铺名＋菜单用途”。

主题 Footer menu 已实际接通 Customer care 栏；有绑定时显示该店页脚菜单，未绑定时保持现有政策／账户链接。新店不复制主店菜单位置或自动添加设置。无菜单内容复制／继承，无业务菜单迁移；只在本地验收，尚未发布。

## 原生页面按店铺管理（0.5.6，本地）

Pages 列表新增店铺筛选和“所属店铺”列，总管理员从菜单进入默认主店；切换后搜索、排序、状态链接及计数保持该店范围，新增页面归属所选店铺。员工仅管理已获授权店铺，原有 Administrator／Shop Manager 页面权限保持。

隐私、退款／退货、配送、服务条款等都使用各店自己的原生页面，独立编辑、发布和修订；现有隐私／Woo 条款页设置、页面ID、正文、公开路径和主题页脚方式保留。页面归属固定，父页面只能选同店且不可成环。区块编辑器仍用原生保存；中央域名编辑其他店铺时，REST 请求保持在已登录主机，通过签名头携带店铺范围。草稿预览可在当前登录主机按页面签名渲染所属店铺，不产生另一域名的登录会话。

旧 Trovesia 单店政策自动安装器在多品牌模块启用时停用，避免按全局 slug 覆盖各店页面。用户最终选择只按店铺区分页面，不建立公共页面模板、继承、品牌变量、模板同步或新的用途绑定层。

## 分类范围与集合层级（0.5.5，本地）

原生 Products → Categories 默认只显示共享分类，不沿用上次品牌Cookie。“分类范围”选择店铺后只列该店的商品集合，搜索、排序及分页保留范围。共享分类仍使用原生创建／编辑；集合名称和管理入口进入完整集合编辑器，回收站集合进入集合回收站。集合不提供原生快速编辑、永久删除或拖动排序；排序在集合管理维护。

集合编辑新增“父级集合”，可设为顶层或选择同店铺未删除集合；禁止自身、子孙级、共享分类和其他店铺作为父级。集合列表、导航、区块选择及 Shop 筛选按层级显示，各集合仍独立选品，不自动汇总子集合商品。删除父集合不连带删除子集合，原层级保留；修改子集合时若父级已在回收站，需重新选择可用父级或顶层。沿用原生ID／slug和既有区块引用；设置或改变父级后，原生分类归档URL会跟随层级改变。

## 批量商品操作（0.5.2，本地）

在原生 Products 筛选“公共商品”、勾选本页商品，选择“批量添加到品牌（草稿）”并应用；确认页选择目标品牌后开始。新品牌可分批继承整个公共目录，每批最多200个父商品，可在 Screen Options 调整每页数量。已有版本（含回收站）跳过，保留其内容、覆盖项及状态；复用媒体文件，不复制评论。

品牌销售版本可批量上架或转为草稿，公共档案跳过。总管理员可添加品牌关联，员工只可变更获授权品牌的商品状态。任务逐件显示成功／跳过／失败，可暂停、刷新后继续和重试失败项；从 Products → 批量任务返回最近任务，记录自最后更新保留24小时。商品不会随任务到期删除，执行需保持任务页打开。不同任务并发建立同一公共商品／品牌时只建立一份。

## 原生 Products（0.5.3，本地）

原生 Products 只有一个商品归属筛选，可选公共商品或某个品牌；总管理员打开页面默认公共商品，不沿用上次品牌Cookie。选择品牌只列该品牌的继承版本，公共来源与品牌版本列可直接跳转。搜索、分页、状态计数与链接保持当前选择；员工仅有获授权品牌选项。

继承商品只展示有效的编辑控件：五组差异未启用时隐藏输入，勾选“单独设置”立即显示；共用分类／标签、规格、税务、运费及下载资料在公共商品维护，品牌编辑页显示来源说明。变体也按各自覆盖状态显示价格、图片、描述；共享规格不提供增删或重选入口，品牌启用状态保留。

继承商品不显示原生快速编辑；当前结果页包含继承商品时不提供混合批量编辑，避免同批字段部分生效。公共商品保留原生编辑能力。插件中的“品牌商品”标签、重复列表和快捷状态入口已移除；全部商品管理使用原生 Products，批量继承／上架／转草稿继续可用。旧列表和编辑链接转到对应原生页面，旧写入请求拒绝。

## 当前能力

- 公共商品档案保存共用资料；各品牌拥有原生 Woo 销售版本。标题、长短描述、图片及售价／促销日程可独立覆盖，未覆盖字段随公共资料更新。变体也支持自己的价格、图片、描述。
- 分类、标签、媒体库真正共用一份原生数据；不再复制各站词表与图片。品牌集合、页面、菜单、Logo、品牌资料和收录设置独立。
- 商品发布状态、排序、评论、购物车、订单归属独立。所有商品／变体不管理库存、始终有货。
- 顾客按品牌注册：同用户名／真实邮箱可分别注册，原生用户 ID、密码、默认地址、会话独立。顾客固定 Customer，不能直接转员工。
- 员工使用独立共享身份，商城总管理员按品牌授权 Administrator／Shop Manager；新品牌不自动授权，独立域名分别登录，无自动 SSO。品牌管理员不拥有商城全局插件、支付、税务、主题配置或跨品牌报表权限。
- 商品、订单、Reviews、用户继续使用原生后台；商城总管理员可在顶栏选择全部／单个品牌。原生商品编辑器新增“公共资料／品牌版本”。不恢复统一订单、独立评论、共享客户或主商品发布标签。
- 中央管理保留五项：概览、品牌设置、商品集合、操作日志、文档与限制。概览的“商品”链接直达对应品牌原生 Products。
- 一套 FluentSMTP 凭据，按订单来源生成品牌邮件身份和链接；本地 MU 层禁止所有实际邮件和支付。

## 使用要点

所有品牌商品都必须继承公共档案，不提供独立品牌商品；品牌特有商品也先建立公共档案，再仅为该品牌生成版本。新增商品仅总管理员操作，品牌归属与公共来源固定，不能解除或更换关联。在原生“产品”中新建公共商品，在“公共资料／品牌版本”选择品牌并保存；销售版本初始为草稿，核对差异后分别发布。编辑品牌版本时，勾选“单独设置”再填写该品牌值；取消勾选并保存即恢复继承。取消目标品牌勾选不会删除已有版本；下架使用该版本原生草稿状态。

原生“用户 → 新增”创建员工，随后在“员工品牌授权”逐品牌分配角色；顾客在各品牌前台注册。商城总管理员由受控平台配置认定，不因授予某品牌 Administrator 自动产生。

## 边界

这是一套商城的逻辑隔离，不是不同数据库或不同 WordPress 安装。货币、税务、运费规则、支付配置、插件及主题代码共用；各品牌不能独立切换主题。支付服务商、退款集成、自动 SSO、多地址簿不在当前范围。真实邮箱允许跨品牌重复，第三方全局按邮箱取用户或自行直查 SQL 的插件必须单独适配。

0.5.0 为当前本地的显式迁移版本，不会在激活／访问时自动转换任意旧站。未初始化时不启动多品牌业务模块；Multisite 仍开启时网页进入迁移维护保护。生产和任意全新安装需另行制定初始化／迁移方案，不能直接套用本地专用脚本。

已有数据、旧站点表和上传文件保留。回滚必须恢复匹配的数据库、源码和配置，不能只重新开启 Multisite；详见 OPERATIONS。停用／卸载默认保留业务数据。

# Group Shop Manager

WordPress Multisite + WooCommerce 的多品牌店铺管理插件。源码 `0.4.0`（本地待发布；用户要求全部改完再通知上线），实际部署状态见 HANDOFF，安装目录 `plugin/group-shop-manager/`。

## 新对话接手顺序

当前本机测试入口：[主店后台](http://www.main.local/wp-admin/admin.php?page=group-shop-manager)。分店使用 www.branda.local、www.brandb.local、www.brandc.local、www.brande.local、www.brandf.local、www.brandg.local；均为 HTTP、无需端口。启动、域名映射与回滚见 OPERATIONS 的“当前本地域名”。旧 localhost 验收脚本有严格保护，不能直接用于此环境。

1. [当前状态与接手事项](docs/HANDOFF.md)：先确认实际已上线版本和未完成事项。
2. [架构与数据约定](docs/ARCHITECTURE.md)：数据归属、权限、共享与隔离边界。
3. [使用说明](docs/USER-GUIDE.md)：店铺、商品、库存、订单、客户、评论、邮件。
4. [部署、验证与回滚](docs/OPERATIONS.md)。
5. [变更记录](CHANGELOG.md)。

项目根目录 `AGENTS.md` 要求所有功能和注意事项变更同步更新文档，不能把计划记为已完成。根目录 `PROJECT-HANDOFF.md` 是复制来的 Trovesia 历史记录，不是本插件规格。

## 已确认范围

- 顾客每店独立注册，可重复使用相同可见用户名和真实邮箱；各店为不同原生用户 ID，密码、默认地址、购物车及会话独立。
- 管理员／Shop Manager 使用独立共享员工身份；由网络超级管理员明确分配店铺权限，新店不自动授权。顾客固定 Customer，不能直接改成员工。
- 不同独立域名需要分别登录，未实现跨域自动 SSO。
- 主店后台集中管理店铺、本店商品编辑、基于共享分类标签的各店商品集合与操作日志。账户使用原生网络用户管理，订单和评论使用所属店原生后台。
- 每店商品内容、售价、发布状态、排序、评论、购物车和订单独立。分类／标签由主站原生“产品 → 分类／标签”统一维护，全站修改生效；分店只有兼容 WooCommerce 的原生投影，不提供独立编辑或覆盖。旧映射商品的分类／标签归属同步继续保留；不再提供新的跨店发布。
- 所有商品及变体不管理库存、始终有货；批量库存功能已移除。草稿仍须明确发布。
- 支付服务商未确定：支付通道管理、退款、付款方式共享不在第一版。
- 不修改 FluentSMTP 核心。按当前原始店铺上下文生成发件身份、回复地址和邮件页脚。
- 不承诺 Google 无法识别品牌关联，不提供对搜索引擎和用户的差异展示。

## 主商品发布已移除（0.3.7，本地）

删除“主商品发布”标签、专用表单／处理器，以及商品／变体跨店复制、字段覆盖、媒体导入和新增发布映射代码。旧 tab=catalog 返回概览，旧 catalog_publish 请求拒绝，Catalog::publish 等发布 API 已移除，不提供替代发布入口。

已有各店商品、变体、图片、历史映射和日志保留；店铺商品编辑、原生富文本／本店媒体、售价、变体和独立上下架继续可用。商品新增和结构调整使用所属店 WooCommerce 原生后台。历史映射继续服务原先确认的统一分类／标签归属同步，不会触发内容或售价复制；无业务数据清理或迁移。

## 多店用户（0.4.0，本地）

继续使用原生“网络管理 → 用户”及各店“用户”，不恢复共享客户标签。列表补充账户类型／所属店和可见登录用户名；网络列表保留首次来源及原生 Sites 当前成员关系。原生 Username 为内部唯一标识，登录使用单独显示的用户名或真实邮箱。

顾客在所属店前台注册，相同用户名和邮箱可在 A／B 店分别创建账户；未注册店铺不能登录，密码重置／地址修改只影响本店。顾客编辑页锁定 Customer，服务器同时拒绝角色升级、跨店加入及超级管理员授予。原生网络“新增用户”创建独立员工，随后在用户编辑页“员工店铺授权”选择各店 Administrator／Shop Manager；只有网络超级管理员可操作，改授权撤销该员工原会话。

前台账户入口优先本店顾客；原生 wp-login.php 后台入口优先员工，处理两类身份邮箱相同的情况。员工账户用于经营管理，下单需独立顾客账户。员工修改密码影响其已授权店铺，顾客改密不影响其他店同邮箱账户。

既有共享顾客必须先显式迁移：原用户保留一个所属店，其余店创建独立 ID，并重绑订单、产品评论、购物车、下载权限和既有付款令牌；历史订单金额、状态、地址快照保留。一次性保留旧密码哈希和默认地址初始值，之后各自独立。未经迁移顾客注册／登录关闭，后台不会自动拆分。操作与回滚见 OPERATIONS。

这仍是同一 Multisite 数据库中的逻辑隔离，网络超级管理员可管理全网；不是物理独立数据库。原生真实邮箱可重复，第三方直接调用全局 get_user_by('email', …) 会有歧义，需使用本店身份接口，不能假定所有第三方 SSO／会员插件自动兼容。已适配当前前台、原生后台、REST 及 WordPress／Woo 隐私工具；顾客应用密码禁用。详见 ARCHITECTURE。

## 评论使用原生 Reviews（0.3.5，本地）

移除“独立评论”标签页及专用审核处理器，统一使用所属店“产品 → Reviews”。原生列表新增只读“所属店铺”列，显示店铺名称与编号，评论及回复均按当前站点归属。审核、回复、编辑、评分／商品筛选和批量操作继续使用 WooCommerce 原生功能及权限；不影响原有精选／评论媒体扩展。

原生列表只显示当前店评论，不是全网络汇总。无需新增或回填评论店铺元数据，原有评论、评分和购买验证按店保留。旧 tab=reviews 回到概览，旧审核请求拒绝。普通 WordPress“评论”列表不增加此列。

## 订单使用原生后台（0.3.4，本地）

移除“统一订单”标签页、跨店合并列表、自建详情及专用备注／状态处理器。概览“店铺入口 → 原生订单”进入所属店 WooCommerce 订单后台，按目标店 HPOS／传统存储模式选择正确地址。原生后台只显示当前店订单，不提供全网络汇总；独立域名可能需要分别登录。旧 tab=orders 链接回到概览，旧写请求拒绝处理。

订单数据与历史备注保留，无业务数据迁移。原有有限状态转换限制随中央处理器退休；原生操作遵循 WooCommerce 权限、通知及网关配置，不代表已接入支付或退款。

## 店铺商品与统一分类（0.3.1，本地）

商品列表显示主图，移除库存列，支持直接上架或禁用（本店草稿）。详情与短描述使用 WordPress 原生富文本；商品主图／相册及变体图片使用本店媒体选择器，可预览、移除、调整主图相册顺序。变体按规格同页编辑价格、启用状态、图片与描述，每页 20 个，可批量填本页价格并一起保存。属性、增删变体、促销日程继续使用所属店原生产品编辑器。

分类／标签不在店铺商品编辑页修改。主站原生分类／标签为唯一权威；原“统一分类”“店铺分类”自建菜单保持删除。升级先转换并清理退休模板元数据，再汇集各店独有的普通分类／标签，按 slug 对应时主站为准，保留分店原生编号和集合规则。集合本身仍按店独立。技术边界、冲突与回滚见 HANDOFF/ARCHITECTURE/OPERATIONS。

## 商品集合（0.3.2，本地）

“商品集合”先显示列表，支持创建、独立编辑页、删除到回收站和恢复。集合包含标题、描述、当前店媒体封面；不再填写网址别名或父分类，系统自动维护内部归档地址，已有网址保持。

选品可只选分类（含子分类）、只选标签、组合两组条件，或直接搜索选入本店商品；支持额外选入、排除与置顶。分类组与标签组同时设置时取 AND。选品搜索覆盖当前店商品库，按名称／编号每次最多返回 25 条，每组选入最多 200 件。

首页／专题：在所属店页面编辑器添加原生“商品集合”区块，选择集合、商品数量／列数、标题／描述／封面和分页；也可用 `[group_shop_collection id="本店集合编号"]` 或主题读取函数。Shop 勾选“在 Shop 商品集合筛选中显示”后，原生经典商店页出现集合筛选，并与原有属性、价格、排序叠加。旧集合默认不自动加入 Shop 筛选。

后台选品、原生归档、页面区块与主题查询使用同一份集合关系。草稿／隐藏商品不在页面模块公开展示。详细用法、兼容范围及限制见 USER-GUIDE 与 ARCHITECTURE。

## 原生分类的类型和店铺归属（0.3.3，本地）

原生“产品 → 分类／标签”列表新增“类型”和“所属店铺／范围”：普通分类／标签标记全站共享；商品集合标记当前所属店铺名称、编号、地址及状态，并提供集合管理入口。原生编辑页也显示相同只读信息。

原生页面只显示当前站点记录，不是所有店铺集合的汇总；其他店集合仍在“多店铺管理 → 商品集合”切换店铺查看。分店原生分类页返回主站的既有行为保持。该改动只补充显示，不迁移数据或修改原生操作权限。

## 店铺设置（0.2.2）

店铺列表每店一行，显示品牌、域名、主题、收录及邮件状态。新增与编辑使用弹窗；编辑包含原有 Logo 媒体选择和品牌设置。新增填写名称与域名后建店，再编辑完善设置。分店域名直接使用原生 Multisite domain/path 和本店 home/siteurl，改域名立即绑定 HTTPS 根路径，主店域名只读。必须提前配置 DNS、Nginx 路由和证书；不会自动迁移正文旧链接、旧域名跳转、第三方回调或邮箱。

## 使用入口

主店 WordPress 后台 → **多店铺管理**。Multisite 模式下只允许网络超级管理员管理；单站模式可查看管理主店，但创建分店需要先完成 Multisite 迁移。

新分店默认禁止搜索收录和邮件，自动接入统一分类／标签。商品在所属店原生后台新增，仍需核对本店内容、售价和原生发布状态。

## 重要限制

- 管理的是同一个 Multisite 网络，独立部署的 trovesia-shop 不会自动加入或共享账户。
- 第一版最多创建 25 家店。订单使用各店原生后台，无中央合并列表；主商品发布和其前 100 件选择器已移除。
- 中央店铺商品编辑继续支持简单／可变商品，变体结构和商品新增使用所属店原生编辑器；无跨店复制。
- 商品内容、价格和图片由所属店独立维护，不提供主商品字段推送／覆盖；旧映射分类／标签归属自动同步保持。没有 AI 文案或自动差异化承诺。
- 图片在各店媒体库独立保存，使用本店原生媒体管理；原商品／变体与媒体跨店导入功能已移除。
- 分类／标签的新增编辑仅在主站原生“产品 → 分类／标签”；商品与集合查询使用受控原生投影。Logo、商品主图／相册及变体图片均使用原生媒体选择，不再填写附件编号。
- 店铺设置的搜索引擎收录选项直接读写原生 blog_public，与“设置 → 阅读”同步；新店默认不鼓励收录，不是访问限制。
- 不再限制原生分类数量；每店最多 50 个未删除集合（含停用）、重建最多 2000 件父商品；每组选品最多 200 件，搜索每次 25 条。回收站保留规则供恢复。
- 商品集合支持共享分类的本店原生投影（含子分类）、标签任一/全部、额外选入、排除与手动置顶。导航通过原生分类菜单或 `[group_shop_collections]` 加入主题，不会自动重写已有菜单。
- 订单列表、详情、备注与状态管理使用所属店 WooCommerce 原生后台及权限；插件保留来源快照、前台归属保护及已有 HPOS 来源列。支付、退款和物流集成仍未配置。
- 每店顾客地址为该独立用户的一组原生默认账单／收货资料，不是多地址簿。
- 禁用邮件时直接阻止发送并记录事件，不提供自动补发队列；开启后不会重放历史被阻止邮件。
- 停用或卸载保留店铺、客户、订单、映射和日志。备份回滚见运维文档。

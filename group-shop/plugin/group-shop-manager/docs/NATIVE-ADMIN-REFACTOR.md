# 原生后台实施状态（0.5.6，本地）

2026-11-04 用户最终选择“一套商城多个品牌门面”，并明确要求关闭 Multisite。当前本地已经迁移为单站。此决定覆盖旧的分站／网络后台／词表投影设计；历史过程见 CHANGELOG 与 qa 中各版本记录。

| 功能 | 当前入口 | 插件职责 |
|---|---|---|
| 品牌设置 | 多品牌管理 → 品牌设置 | 域名／UUID／Logo／展示与邮件资料；不创建原生站点 |
| 商品 | 原生 Products／Product data | 公共档案与必须继承的品牌销售版本，五组覆盖、变体差异、公共／品牌单一筛选（默认公共） |
| 批量商品 | 原生 Products → 批量操作／批量任务 | 公共商品继承为品牌草稿、品牌状态操作、进度／暂停／失败重试；不覆盖已有版本 |
| 旧品牌商品页面 | 已退休，旧GET引导原生 Products | 列表／编辑／快捷状态移除，旧写入410拒绝，原生品牌版本保留 |
| 分类／标签 | 原生 Products 分类／标签 | 分类默认共享，可按店铺只查看对应集合；搜索／分页同范围；标签共用 |
| 页面 | 原生 Pages／区块编辑器 | 店铺筛选、归属列、固定归属和同店父级；独立内容与状态，不建模板继承 |
| 商品集合 | 中央集合列表／编辑页／回收站；原生分类集合行可跳转 | 同店parent层级、独立规则／成员、嵌套导航及区块／Shop选项；不自动汇总子集合 |
| 订单 | 原生 Woo Orders | 来源快照、当前品牌查询、顾客归属、原生权限及邮件身份 |
| 评论 | 原生 Products → Reviews | 所属品牌列、查询与编辑范围；无自建审核器 |
| 用户 | 原生 Users／新增／资料页 | 身份类型、品牌／首次来源／可见用户名、固定 Customer、员工逐品牌授权 |
| 日志 | 中央操作日志 | 最小动作／编号／计数，保留历史 |

五个中央标签为概览、品牌设置、商品集合、操作日志、文档与限制。统一订单、独立评论、共享客户、主商品发布标签保持删除，旧处理器不恢复。

新的公共档案由最新明确授权引入，在原生 Woo 编辑器中管理，没有恢复旧的 Multisite 发布器、媒体复制器或旧映射写入 API。各品牌仍有真正原生销售商品，原生结账直接使用该版本成交价。

普通单站 Administrator 具有商城全局权限，所以品牌管理员使用受控能力白名单。总管理员通过顶栏切换品牌或全部；原生区块编辑器通过已签名品牌上下文访问 REST。品牌员工不开放商城全局 Analytics／Settings／插件管理。

实现、数据转换与限制见 ARCHITECTURE、HANDOFF、OPERATIONS。没有将简化商品页的整体移除或任意第三方插件兼容写成完成；没有生产发布授权。

0.5.1 已补齐原生 Products 的品牌／资料类型筛选、来源／版本关系与跳转、状态计数和筛选保留。继承字段按有效性显隐，公共字段只在公共档案编辑；变体相同原则，服务端恢复继承并校验结构操作。品牌商品标签未移除；移除该标签仍需后续明确要求。

0.5.3 已将两项筛选合并为单一公共／品牌选择并取消独立品牌商品；新增公共仅总管理员，关联与归属固定。品牌特有商品也先公共再继承，五组差异仍可覆盖。当前规则覆盖上文0.5.1历史筛选形式。

0.5.4 用户已明确移除品牌商品标签及重复管理功能；旧页面跳转原生，旧写入停用，覆盖上文“等待移除授权”的历史描述。商品集合仅评估，详见COLLECTIONS-ASSESSMENT.md。

0.5.5 用户已授权原生分类范围切换与集合parent层级，已在本地实现并验收；覆盖上一轮“集合仅评估”的实施状态。中央集合入口与底层product_cat保留，未迁移独立taxonomy。

0.5.6 用户最终要求页面只按店铺区分，不做模板继承。原生Pages与编辑器扩展已实现；没有新增中央标签、同步器或用途绑定页面。

# 使用说明

**当前 0.4.0 仅在本地测试，未发布线上。用户通知全部改完后才允许上线。**

## 进入后台

使用网络超级管理员登录主店，在左侧找到“多店铺管理”。非管理员无法访问中央数据或提交写操作。顾客在各店独立注册；员工使用按店授权的独立共享身份，独立域名分别登录。

## 新增店铺

“店铺设置”显示店铺列表，每店一条记录，包含名称/Logo、域名地址、主题、收录和邮件状态。点击“新增店铺”，在弹窗填写名称与域名，点击“创建店铺”。自动接入主站统一分类／标签，不复制历史订单、评论、客户、SMTP 或支付配置。主题可在店铺设置中选择。新店禁止收录，客户邮件关闭。

在该店铺一行点击“编辑”，在弹窗编辑域名、名称、说明、主题、Logo、搜索引擎收录、发件名称、发件邮箱和客服邮箱。保存成功关闭弹窗并刷新列表；关闭或 Escape 取消未保存改动，保存失败保留输入以便修正。主题必须已安装并在网络启用。

Logo 点击“从媒体库选择图片”，可在该店原生媒体库选择已有图片或上传新图，点击“使用此图片”后预览，再“保存店铺设置”。更换重复选择；移除点击“移除 Logo”并保存。图片不会跨店混用，不再填写附件编号。Logo 按店保存，更换主题后保留；原生 Logo 设置使用同一店铺引用。不同主题仍须使用原生 Logo 输出或相应适配。

“搜索引擎收录”提供“不鼓励搜索引擎收录（建站中）”和“允许搜索引擎收录”。直接关联原生 blog_public，与该店“设置 → 阅读”双向同步，新店默认不鼓励。关闭收录时 WordPress 输出默认 noindex；允许后仍受各页面 SEO 规则和搜索引擎处理影响，不保证立即收录/移除，也不阻止访客或不遵循规则的爬虫访问。保存只影响当前所选店，升级不改变已有收录状态。

域名填写完整主机名，例如 `test.animecats.online`，也可粘贴 `https://test.animecats.online/`，不能包含路径、端口、通配符或 http://；国际域名使用 Punycode。已有路径式店铺在域名未变时保留原路径。更换域名立即将该分店绑定到新 HTTPS 域名的根路径，不改变店铺编号、UUID 或历史订单来源。域名不能被其他站点占用（含已停用站点），主店域名只读，需由运维协调网络常量及统一后台地址。

**先配置 DNS、主机 Nginx 指向当前安装和 HTTPS 证书，再保存域名。** 插件不验证公网路由是否已就绪，不自动处理旧正文/媒体绝对链接、旧域名 301、第三方支付回调或外部授权；有内容的店铺改域名前应备份并安排序列化安全链接迁移和 HTTP 验收。现有附件/订单数据本身不复制或删除。先完成邮件、首页、政策及客服文案的逐店审核，再开启收录；现有 Trovesia 模板中的营销文字和历史政策不会被自动重写。插件只更新 WordPress 原生域名绑定，不自动配置 DNS、服务器、证书或邮箱。

当前第二店铺为 `https://test.animecats.online/`（店铺编号 2），原 `/demo-store/` 自动跳转到新域名。这是历史线上环境；本地 0.4.0 已改为顾客每店独立，员工按店授权。新域名需要单独登录；统一管理仍从主店的“多店铺管理”进入。

## 店铺商品（主商品发布已于 0.3.7 移除）

“主商品发布”标签及功能已删除，不再从主店复制商品／变体、导入图片或按字段覆盖分店。旧发布地址返回概览，旧提交拒绝处理。新增商品、属性和变体结构通过所属店 WooCommerce 原生“产品”后台管理。

已有商品、变体、图片、历史映射和日志保持，不需要迁移或重建。历史映射仍用于既有分类／标签归属同步；商品内容、价格和图片由所属店独立编辑。无限库存与人工确认上架状态的规则保持。

“店铺商品”列表显示主图、名称、状态／类型、价格和排序，不再显示库存列。每行可“禁用商品”（本店商品变成草稿）或“上架商品”。只影响所选店铺，不影响原商品或其他店铺版本。被禁用的商品仍在后台列表中，普通顾客无法在该店商品页、搜索、归档及 Store API 访问；重新上架可恢复展示。

点击“编辑商品”可编辑本店名称、详情、短描述、售价、排序与原生发布状态。详情与短描述使用原生富文本，支持格式、列表、链接及插图，也可切换代码。图片选择器直接使用本店媒体库，可上传／选择、预览、移除，主图／相册通过“前移／后移”调整，第一张为主图。最多 100 张；变体只选一张，留空沿用商品主图。保存后生效，无需填写附件 ID。

可变商品直接在同一页面按规格编辑普通价、促销价、启用状态，展开“图片与描述”编辑该变体图片和描述。每页 20 个变体，批量填价和“清空本页促销价”只影响本页，之后点“保存商品与本页变体”。切页前先保存；有未保存修改时浏览器会提示。促销价必须低于普通价，留空取消价格；原生促销日程保留，日程、属性和增删变体通过页面原生编辑器链接操作。禁用变体与禁用整件商品分别控制。

保存会先校验整页的商品和全部变体；输入错误不会先保存其中几行，并会保留当前管理员上次输入 120 秒供修正（超过 200 KB 不保留）。检测到表单被 PHP 截断时拒绝写入。运行时数据库／插件异常仍不是跨商品数据库事务。不再存在主商品内容字段覆盖入口；第三方视频、外部链接、短代码和加购业务 ID 仍需在所属店原生编辑器检查。

## 全站统一产品分类与标签（0.3.1）

用户最新决定：分类和标签只有一份权威数据。进入**主站**原生“产品 → 分类／标签”（Products → Categories／Tags）新增、编辑或删除。名称、slug、介绍、父级、封面与排序修改会同步到活动分店。分店相关页面会返回主站，不能创建独立词表；“店铺商品”不再编辑分类与标签。

修改某件主商品的分类／标签归属，使用主站原生产品编辑器；历史映射关联的分店商品仍同步归属，内容、价格、发布状态、评论、订单不受影响。只在分店独立创建且没有主商品映射的商品，可以在该店原生商品编辑器选用统一词表。集合归属仍由各店规则管理。

升级先处理旧模板元数据，再把各店独有的普通分类／标签汇入主站。相同 slug 以主站为准，默认分类统一到主站默认项；保留分店已有原生编号、商品与集合。已有分店差异名称、层级或归属会按照新统一规则改变。商品集合不汇入共享词表；如果其 slug 与统一分类冲突，后台提示修正后重试，不静默覆盖。

分类／标签原生数据写入成功而某分店同步失败时，后台显示错误，下一次网络管理员进入后台会重试。停用站点在重新启用后补同步。删除规则依赖的共享分类／标签会停用相关集合并提示重新选条件，避免误选全部商品。旧“统一分类”“店铺分类”自建页面及继承／覆盖操作继续删除。

## 在原生分类中识别集合归属

“产品 → 分类／标签”列表的 **类型**、**所属店铺／范围** 两列用于区分：

- 普通产品分类／标签显示“共享分类／共享标签”“全站共享”，由主站统一维护。
- 商品集合显示“商品集合”、启用／停用／回收站状态，以及所属店铺名称、主店／店铺编号和地址。截图中的“首页热门商品（本地验收）”属于主店 Group Shop QA（#1）。

原生分类编辑页也有相同的只读归属说明。点击集合行的店铺名称或“管理商品集合”，进入该店对应集合；已删除集合进入回收站，缺失规则的标记项进入本店集合列表。

原生分类列表只显示当前站点的记录，不会把其他站点的原生表合并进来。查看其他店集合，请通过页面提示进入“多店铺管理 → 商品集合”并切换店铺。分店原生词表页面仍返回主站统一维护。中等及较窄桌面宽度会优先显示完整列表，将原生新增表单放在列表下方，避免归属列拥挤。

## 商品集合：列表、新建和编辑

先选择店铺。“商品集合”默认只显示列表，每行显示封面、标题／描述、选品方式、已发布商品数、展示位置和状态；点击“创建集合”打开独立编辑页，点击行内“编辑”修改已有集合。

填写集合标题和描述，在“集合图片”使用当前店原生媒体库选择或上传封面。描述遵循原生分类描述允许的 HTML。无需填写网址别名或父分类；系统内部自动生成稳定地址，修改标题不会更改地址，旧集合已有地址和关联继续保留。集合按店独立，不会因为共用分类／标签而自动复制到其他店铺。

选品方式：

- **根据分类／标签筛选**：可只选分类、只选标签或同时选。分类勾选多个时匹配任一，包含真实子分类；标签可选“任一”或“全部”。分类组和标签组同时设置时，两组都需满足，规则至少选择一组条件。
- **直接选择商品**：在“选入商品”按名称或商品编号搜索当前店商品，点击“选入”；取消已选项的勾选即可移除。搜索覆盖当前店商品库，每次最多显示 25 条，结果较多时缩小关键词。每组选品最多 200 件。
- 规则模式仍可“选入商品”作为补充；“排除商品与展示排序”中可排除商品，排除优先于规则及手动选入。
- 商品排序支持店铺排序、名称、最新或手动置顶。置顶项必须已经符合规则或选入集合，用上下按钮调整；其余符合条件的商品继续显示。

在展示设置勾选“启用集合”、需要时勾选“在 Shop 商品集合筛选中显示”或“显示在集合导航中”，再保存。旧集合不会被自动加入新增的 Shop 筛选。集合排序只控制集合选项／导航顺序；商品排序控制集合内商品顺序。

集合不改变商品发布状态。草稿、禁用／私有商品不会在前台模块展示，原生隐藏商品也不会出现在该模块。列表商品数沿用 WooCommerce 原生分类已发布数量，可能包含设为隐藏的已发布商品；公开模块再按 Woo 可见性过滤。

## 首页模块、专题页面和 Shop 筛选

首页／专题采用所属店原生页面编辑器：添加 WooCommerce 类别下的 **“商品集合”** 区块，选择已启用集合；设置每页商品数（1–48）、列数（1–6）、是否分页，以及是否显示集合标题、描述和封面。区块预览和前台沿用主题的 Woo 商品卡片。首页热门模块可选择“热门商品”集合；专题页可选择对应专题集合并启用分页，后续调整后台集合会同时更新这些展示。

经典编辑器或短代码区块可使用：

```text
[group_shop_collection id="本店集合编号" limit="8" columns="4"]
[group_shop_collection id="本店集合编号" limit="12" columns="4" paginate="yes" image="yes"]
```

默认显示标题和描述，封面默认不显示；用 `title="no"`、`description="no"` 关闭。已保存集合编辑页的“用于首页或专题页面”提供当前集合示例。分页按集合编号独立，不会覆盖整页主查询分页。不会自动替换当前主题已经写死的首页模块；需在目标模块选择集合区块，或由主题使用读取接口。

原生经典 Shop 在勾选对应展示设置后自动显示“商品集合”筛选。选择集合会与已有原生属性、价格、搜索和排序共同生效，切换时重置分页。顾客主动选择排序时遵循其选择；没有指定排序时使用集合排序。无结果仍保留筛选表单，失效／停用／删除／非本店集合不会退回展示全部商品。

主题也可放置 `[group_shop_collection_filter]`，或通过 `group_shop_collection()`、`group_shop_collection_query_args()` 读取当前店数据（开发约定见 ARCHITECTURE）。Shop 自动筛选针对 Woo 经典主查询；使用 Store API 独立查询的原生 Product Collection／Filter 区块或第三方 AJAX 商品列表，不会自动读取 `gsm_collection` 参数，须由主题适配或使用本插件“商品集合”区块。原生 Store API 的 category 条件仍能使用集合成员关系。

## 删除、恢复和导航

行内“删除”会移入集合回收站，移除集合派生成员、导航、区块输出和 Shop 筛选，旧集合归档返回 404；商品本身、共用分类／标签、图片和规则均保留。回收站点击“恢复集合”会重建关系并恢复此前启用／导航设置。若期间规则依赖的分类／标签被删除，集合保留待修正状态，不会自动启用。当前没有永久清空入口。

停用与删除不同：停用保留正常集合列表和原有归档地址，清空集合成员，页面模块与筛选停止显示；删除进入回收站。最多 50 个未删除集合（包括停用），回收站不占这个上限，恢复时仍检查上限。

导航不会覆盖已有菜单。可用原生归档链接或 `[group_shop_collections]`，只显示当前店启用且勾选导航的集合。

重建支持每店 2000 件父商品。商品保存、分类／标签及层级变更会更新关系；并发锁冲突时标记待重建并有限重试，必要时从列表“集合维护”重建。第三方直写数据库后需显式重建核对。保存错误会私有保留本管理员表单 120 秒（最多 200 KB）；表单截断会拒绝写入。

## 无限库存

0.2.0 已移除“批量库存”。全网络商品及变体统一不管理数量、始终有货，原生保存也会维持该策略。现有商品升级时通过 WooCommerce CRUD 迁移元数据和商品 lookup；订单不再扣减这些商品数量。草稿、私有、售价、购物车及其他购买限制仍各自有效，不会因为有货自动上架。

## 订单

0.3.4 移除“统一订单”标签页。使用“概览 → 店铺入口 → 原生订单”，或进入所属店“WooCommerce → 订单”，查看列表、筛选、明细、地址、备注并修改状态。入口自动适配该店 HPOS／传统存储模式。原生后台仅显示当前店订单，不再提供全部店铺合并列表；独立域名可能要求重新登录。

状态修改、内部备注／客户备注、邮件和其他订单操作遵循 WooCommerce 原生权限与配置，中央旧有的有限状态转换限制不再适用。原生页面可出现支付／退款相关操作，但插件未新增网关、退款或物流集成，能否实际执行取决于已安装配置。

订单、历史备注和来源快照不删除；前台客户归属保护及已有 HPOS 来源列保持。旧中央订单地址回到概览，旧备注／状态请求提示未知操作。订单原生地址和内容是下单快照，不随默认地址或商品标题修改。

## 顾客与员工（0.4.0，仅本地）

“共享客户”标签继续删除。使用原生 **网络管理 → 用户** 管理全网身份；各店原生“用户”只管理当前店成员。列表新增 **账户类型／范围** 和 **店铺用户名**，网络列表另保留首次来源和原生 Sites。原生 Username 是系统唯一编号式标识；日常登录使用“店铺用户名”或真实邮箱。可用原生搜索、Screen Options 和用户编辑器。

顾客在所属店的 My Account／现有登录弹窗注册。A 店 user1、user1@mail.com 与 B 店相同资料是两个账户，可设置不同密码。未注册 B 店时不能用 A 店身份登录。密码重置和默认地址只作用于当前店；订单地址始终是历史快照。普通 wp-login 注册入口会引导到本店 WooCommerce 账户页。

顾客账户类型不可变：编辑页锁定 Customer，不能改成 Administrator、Shop Manager 或网络超级管理员，也不能把同一个顾客 ID 加入其他店。该限制同时在服务端执行，适用于伪造表单和原生角色 API。需要员工时创建另一个员工身份，可使用相同邮箱。各店管理员／Shop Manager 只能在原生权限允许下编辑本店顾客，不能直接取得其他店顾客资料。

**创建员工**：网络超级管理员进入“网络管理 → 用户 → 新增”，按原生 Multisite 规则填写用户名（小写英文字母／数字）与邮箱。创建后编辑该用户，在“员工店铺授权”逐店选择“不授权”“Shop Manager”或“Administrator”，保存。新员工没有默认店铺权限，新店也不自动授权；普通管理员和 Shop Manager 无权为员工自行加店。授权变更撤销该员工旧会话。员工身份用于管理，下单使用独立本店顾客身份。

前台 My Account／弹窗优先匹配本店顾客；后台 wp-login.php 优先匹配员工。当同邮箱同时有顾客与员工时，分别使用上述入口。员工密码在已授权店铺共用，顾客密码仅本店有效。员工忘记密码可从有权限店铺或主店后台入口发起。不同域名均需分别登录，无自动 SSO。

现有共享顾客已在本地测试库迁移，首次以原密码登录各原有关联店；迁移时复制的初始默认地址之后不再同步。网络超级管理员身份保持；历史管理员／Shop Manager 身份保持原授权。如果原员工同时仅以 Customer 身份加入某店，该店改成独立顾客，不因此获得员工权限。来源／Sites 为来源与成员关系，不是广告归因。

原生“工具 → 导出／擦除个人数据”按当前店的真实邮箱解析顾客，不合并其他店同邮箱用户；订单擦除仍遵守 Woo 原生配置。原生数据库仍由同一网络管理，网络超级管理员可看到全网身份，这不是物理隔离。第三方会员／SSO 或直接全局按邮箱查询用户的插件，需要单独适配；顾客应用密码不可用。上线迁移与成套回滚见 OPERATIONS，当前未上线。

## 评论

0.3.5 移除“独立评论”标签页，进入所属店 **产品 → Reviews** 管理。原生列表新增只读 **所属店铺** 列，显示“店铺名称（#编号）”（实际格式如 `Brand A renamed (#6)`），评论和回复都显示当前所属店。可通过原生 Screen Options 显示／隐藏此列。

查看、审核、回复、快速编辑、评分／商品筛选和批量操作全部沿用 WooCommerce 原生后台与权限，原有精选／评论媒体列保持。原生页面只列当前店数据，其他店需进入其后台，独立域名可能需要分别登录；新增列不会将主站变成全网评论汇总。

评论、评分、数量及已购买验证继续由该店 WooCommerce 数据计算；各店评论独立保存。无需迁移或新增评论店铺字段。旧中央地址返回概览，旧审核请求拒绝；历史评论与审核审计保留，后续原生审核不再产生中央 review_moderated 日志。普通 WordPress“评论”页面保持原样。

## 邮件

在主店 FluentSMTP 配置各店的授权发件身份及精确 From 路由，再启用该店邮件开关。开关不是投递测试，必须验证发件地址未被 FluentSMTP 强制覆盖，域名完成 SPF/DKIM/DMARC，实际投递符合预期。

新店默认阻止发信，事件记入操作日志；开启后不会自动补发之前被阻止的邮件。注册／密码邮件来自当前店，后台操作订单邮件来自订单所在店。顾客重置仅影响本店，员工密码适用于已授权店铺；邮件范围提示按身份区分。

## 日志与文档

“操作日志”展示最近 100 条操作。每次功能、注意事项或部署变更都必须同步维护 CHANGELOG、HANDOFF 和相应文档。后台“文档与限制”列出接手路径和当前边界。

订单状态变化仍可能触发 WooCommerce 原生通知；无限库存只改变供货策略，不代表付款成功，也不替代支付确认。

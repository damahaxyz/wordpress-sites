# 使用说明：单站多品牌（0.5.10，本地）

## 后台与品牌选择

打开 http://www.main.local/wp-admin/admin.php?page=muti-storefront-plugin&gsm_brand=0 。现在是普通单站后台，没有网络管理。总管理员通过顶部“品牌”选择全部或某个品牌，原生产品、订单、用户、评论等列表跟随选择。品牌员工只看到授权范围，独立域名仍需分别登录。

多品牌管理保留概览、品牌设置、商品集合、操作日志、文档与限制五个标签；商品统一使用原生 Products。统一订单、独立评论、共享客户和主商品发布标签不恢复；旧链接回概览，旧写请求拒绝。

## Products 列表筛选与跳转

顶部只有一个“商品归属”筛选：公共商品或某个品牌。总管理员打开 Products 默认公共商品；选品牌后只显示其继承版本。即使刚在其他页面切换过品牌，再从 Products 菜单进入也默认公共。状态、搜索、分类、排序及分页仍可组合使用，计数与状态链接保留当前品牌。公共商品行列出各品牌版本，可直接点击编辑；销售版本可跳回公共来源。员工仅可选择获授权品牌，默认当前授权品牌，无公共维护入口。

品牌员工只可查看授权品牌，品牌归属和公共档案关联显示为只读文本，不能通过表单更换来源。总管理员的原生编辑链接携带目标品牌，经典 Woo AJAX 也固定到该编辑页的品牌，避免多个标签页互相改变操作范围。

## 为新品牌批量继承公共商品

1. 用商城总管理员打开 Products，商品归属选择“公共商品”。先用分类、搜索等条件缩小范围。
2. 勾选需要的商品（表头全选仅当前页），批量操作选择“批量添加到品牌（草稿）”，点击 Apply。
3. 确认商品清单，明确选择目标品牌，点击“确认并开始批量处理”。最多200个不同父商品；Screen Options 可调整每页数量，更多商品分批操作。
4. 保持任务页打开，系统逐件建立继承草稿。成功项提供“查看版本”；已有版本（含回收站）会跳过，不覆盖标题、价格、差异或发布状态。可变商品连同公共规格和变体建立，图片复用，评论不复制。
5. 点击“查看该品牌商品”，核对标题、图片、价格后勾选销售版本，选择“批量上架品牌商品”。需要停售时选择“批量转为草稿”。两者都只变更所选销售版本；公共商品、已经是目标状态或执行前状态被其他人修改的商品跳过。

进度页可暂停／继续，失败时可点“重试失败项”；已成功项不会重跑。从 Products → 批量任务可进入最近任务，浏览器关闭或连接中断后可返回继续。任务记录从最后更新起保留24小时，到期重新选择即可，已生成的商品仍保留。添加到品牌仅商城总管理员可用；员工只能变更获授权品牌商品的状态。不是整批原子事务，部分失败不回滚成功项。

如果看到“版本未完整建立”，先打开关联草稿检查并点击 Update，确认规格／字段完成后重试；系统不会另建重复版本。回收站已有版本应先恢复该版本，再检查和上架。

## 公共商品与品牌版本

1. 在原生“Products → Add new product”添加商品，照常设置简单／可变类型、共用分类、标签、规格和默认内容。
2. 新建页固定为公共商品；在 Product data 的“公共资料／品牌版本”勾选需要销售的品牌并保存。
3. 系统创建这些品牌的原生草稿商品。进入对应版本，勾选需要“单独设置”的标题、描述、短描述、主图相册或价格／促销日程，再使用原生字段填写。
4. 核对各版本的标题、图片、价格和规格，分别发布。公共档案本身不在门面出售，品牌版本不会因公共资料发布而自动上架。

未勾选的字段继承公共值，对应编辑输入会隐藏；勾选后立即显示原生输入。分类／标签、规格、税务、重量尺寸、运输类别、购买备注及下载资料在公共档案维护，品牌编辑页隐藏这些不可独立保存的控件，并显示来源说明。未勾选的字段继承公共值，修改公共档案后会更新已关联版本；已勾选字段保持品牌值。取消覆盖并保存即恢复当前公共值。分类、标签、规格等共用；版本上架状态、排序、评论和销售记录独立。可变商品在原生变体面板单独勾选价格／图片／描述差异；父商品整体价格覆盖优先。

不再提供独立品牌商品。品牌特有商品同样先建公共商品，再只给该品牌创建版本；其他品牌不会自动获得或上架它。新增公共商品由商城总管理员操作；品牌商品的归属和公共来源显示为固定资料，不能解除或更换。不同品牌商品的内部 SKU 必须唯一；迁移保留的业务 SKU 在元数据中记录，不把数据库唯一 SKU 改成重复值。

取消公共档案的目标品牌勾选不删除已有商品；停售请将该销售版本改为草稿。不要用删除公共规格代替处理历史订单；关联变体结构改变须先在本地验证。所有商品／变体不管理库存，始终有货；这不代表支付已开通。

继承变体保留 SKU、条码、启用状态和可独立设置的价格／图片／描述；规格只读，不提供新建／生成／删除变体入口。公共规格和默认选项请回公共档案修改。若修改了父商品的继承开关，先“更新”商品，再编辑变体；界面会提示并暂时收起变体行。变体批量操作仅保留启用切换，避免批量覆盖不同继承状态。

“品牌商品”标签、重复列表及快捷上架／草稿已移除。原生 Products 管理所有商品及批量操作；旧列表链接跳到对应品牌列表，旧编辑链接跳到原生商品页，缺省跳公共目录。旧保存／状态表单已停用，需在原生页面重新操作。

继承商品不显示快速编辑；列表当前页包含继承商品时不提供原生混合批量编辑，回收站操作仍保留。公共商品的原生快速编辑继续可用。所有商品的无效库存控件保持隐藏。

## 分类、媒体和集合

原生产品分类／标签只有一份，全商城共用，在原生页面维护。Products → Categories 默认显示“共享分类”，不沿用先前选择的品牌；使用“分类范围”选择店铺，只查看该店商品集合。搜索、分页和排序保持当前范围；标签页仍为共享标签。集合名称或“管理商品集合”进入集合编辑器；店铺集合视图不提供原生新增、快速编辑、永久删除和拖动排序。Woo 自带的 Product brands 是商品制造商品牌分类，不等于本插件的品牌门面注册表。

媒体库共用原生附件：同一图片可以用于多个门面和商品，不再复制文件。总管理员删除共享图片会影响所有引用；品牌员工不能永久删除共享附件。

商品集合按品牌保存。选择品牌后新建集合，设置标题、描述、封面，按分类子树、标签或搜索手选商品；可以额外选入、排除和置顶。分类组与标签组同时设置取 AND。搜索每次 25 条，每组选品最多 200 件；每品牌最多 50 个未删除集合，重建最多 2000 个父商品。

集合编辑的“父级集合”可选择顶层或同店铺未删除的集合，支持多层关系；自身、子孙集合、共享分类及跨店集合不能作为父级。列表／导航／Shop筛选和区块选择体现层级，各集合仍按自己的规则选品，不自动包含子集合商品。改变父级保留ID和slug，原生归档网址随层级改变。

删除父集合不连带删除子集合，原层级保留，子集合仍可独立使用；父级恢复后关系仍在。若在父级已删除时编辑子集合，需重新选择有效父级或顶层。删除集合进入可恢复回收站，不删除商品、普通分类或图片。缺失规则依赖会停用并提示检查，避免意外显示全店商品。其他品牌私有集合不出现在本品牌原生分类选择器。

首页／专题使用原生“商品集合”动态区块，或 `[group_shop_collection id="本品牌集合编号"]`；导航可用 `[group_shop_collections]`。经典 Shop 可勾选集合筛选，与原生价格、属性、排序叠加。Woo 独立 Product Collection／Filter 区块不会自动解释插件集合规则，需要明确指定原生分类条件或主题适配。

## 顾客和员工

顾客在每个品牌前台单独注册。相同 user1／user1@mail.com 可在 A、B 分别建立不同原生用户 ID；密码、默认账单／收货地址、购物车和会话不互相同步。密码重置链接仅在所属品牌有效。顾客固定 Customer，原生编辑页不能将其提升为员工，需要另建身份。

商城总管理员使用原生“Users → Add User”创建员工，再进入“员工品牌授权”逐品牌选择 Shop Manager 或 Administrator。保存完整授权后旧员工会话撤销，需重新登录。新品牌不会给旧员工自动授权。

Shop Manager 管理本品牌商品、订单、优惠券、顾客和评论；品牌 Administrator 另外可编辑本品牌页面／文章。品牌 Administrator 不等于商城总管理员，不能安装插件、改全局设置或授权其他员工。商城总管理员清单由受控平台配置维护。

前台账户入口优先本品牌顾客，原生 wp-login.php 后台入口优先员工；两者可同邮箱。员工用于经营，下单另用顾客身份。原生用户表中的内部用户名是唯一技术标识，登录使用列表展示的可见用户名或真实邮箱。

## 订单、评论与邮件

订单全部进入 Woo 原生 Orders，Reviews 使用原生产品评论页面，列中显示所属品牌。总管理员可选择全部或单个品牌，员工限授权品牌。审核、回复、订单备注／状态继续使用原生操作；修改状态仍可能触发原生通知。评论和评分属于各自品牌商品，不共享评论。

订单历史金额、地址和来源快照不随品牌改名或后台切换改变。货币、税务、运费和支付设置属于同一商城，由总管理员维护；支付服务商／退款集成尚未接入。

品牌设置配置发件人和客服地址，FluentSMTP 凭据统一管理；品牌实际发信需匹配精确 From 路由及域名邮件配置。订单通知／后台重发会使用订单品牌的链接、发件人和页脚。禁用时不发送、无自动重放队列。本地 QA 额外阻止所有邮件投递和真实付款。

## 品牌门面与上线

“品牌设置”可以新增门面，填写域名和名称；自动创建本品牌原生页面，默认 noindex、关闭邮件、Logo 为空，不复制历史订单和评论。共用一套主题代码，品牌 Logo、首页内容和展示选项独立；不能给各品牌安装不同主题。

域名需事先配置 DNS、服务器路由和 HTTPS；插件不会申请证书或配置代理。仅本机 .local 允许 HTTP。主商城后台域名只读。更换域名后，正文绝对链接、旧域名跳转及第三方回调需独立迁移。

搜索收录开关按品牌读写原生 blog_public，不等于访问限制。所有当前测试门面只在本机 loopback；本地为前台验收关闭 Woo Coming Soon，不代表生产开放。当前版本未发布，生产须另获明确通知并制定迁移方案。

门面地址使用独立的公开路径标记；本版本收起不能改变门面地址的原生内部 slug 编辑框和快速编辑 slug 控件。需要变更门面路径时应另行处理地址、冲突与旧地址跳转，不通过这些内部字段修改。

## 各店独立页面（0.5.6）

在原生Pages列表选择店铺，再搜索、编辑或新增页面。总管理员直接从Pages菜单进入默认主店；列表的“所属店铺”和编辑页只读面板标明归属，保存后不能改到其他店。相同店铺的页面可以设置父子关系，跨店父级及循环关系会拒绝。

隐私政策、退货退款、配送和条款页面均在各店分别编辑，页面标题、正文、草稿／发布与修订独立。现有原生隐私页／Woo条款页设置继续使用，现有网址和页脚路径保持。不同店不会因为编辑了同标题页面而同步内容；没有公共模板或继承选项。

中央后台可直接保存获授权店铺的区块页面。预览草稿时使用带签名的当前登录主机链接，内容按所属店铺显示；复制给未登录访客不会开放草稿，也不会自动登录其他域名。品牌Administrator仅管理获授权店铺页面，Shop Manager原有页面限制保留。

## 原生菜单按店铺管理（0.5.7，本地）

外观 → 菜单新增“菜单所属店铺”切换，总管理员直接进入默认主店。每店可建立多个菜单，Primary／Footer 位置及自动添加页面设置独立。左侧商品、页面、文章只显示本站已发布资料；商品只使用品牌销售版本，排除公共档案。Product categories 包含共享分类与本站启用且未回收的集合，标签仍共用。自定义链接限本站域名、以 `/` 开头的相对路径或 `#` 锚点，不提供外部链接。

服务器在原生表单或 AJAX 写入前校验店铺签名、菜单／菜单项归属、资源与父项；阻止跨店资源、其他菜单的菜单项、循环层级和跨店位置绑定，非法混合保存不会先改菜单名。前台按域名读取位置，并过滤历史无效／跨店条目；不自动删除既有资料。页面自动添加在归属写入后按页面所属店铺执行。

品牌 Administrator 使用“店铺菜单”入口，只授予菜单页面和受控 AJAX 所需能力；不获得主题、插件或全局设置权限，Shop Manager 权限保持。经典原生编辑器是当前受支持入口，Customizer 菜单组件及菜单相关 REST 编辑入口关闭，第三方菜单编辑器需另行适配。WordPress 菜单名称仍全站唯一，建议使用“店铺名＋菜单用途”。

主题 Footer menu 已实际接通 Customer care 栏；有绑定时显示该店页脚菜单，未绑定时保持现有政策／账户链接。新店不复制主店菜单位置或自动添加设置。无菜单内容复制／继承，无业务菜单迁移；只在本地验收，尚未发布。

## 0.5.8 商品展示继承与店铺独立加购（本地）

保留 Trovesia add-ons，按店铺独立配置，不继承公共商品规则。公共商品的 add-ons 面板仅提示进入品牌版本配置；品牌版本的选择器只列同店其他简单商品及具体变体。保存前验证完整表单、原生编辑授权和同店关系，拒绝公共／跨店／自身关联；最多20条规则。原生元数据写入也校验归属，现有规则不自动复制或删除。

加购时核对规则与商品，子项不继续触发嵌套加购。购物车重算检查真实父行、规则、子商品及变体、所属店铺与可购买状态；规则删除、换绑或商品不可用时移除失效加购并提示重选，不再使用旧价格快照兜底。跟随价格／固定价／折扣继续可用，数量跟随主项；加购价不污染同一商品的普通购物车行。独立原生订单行、父项移除联动及普通迷你购物车数量按钮保持。

Product presentation 默认动态继承公共商品，涵盖Eyebrow、Key benefits、退货说明、配送说明、Order activity文案及原有配送天数元数据；公共修改即时生效，不向品牌批量复制文案。在该面板勾选“单独设置本店展示信息”后可独立编辑，取消勾选并保存恢复当前公共值。留空仍使用Trovesia原有默认文案；自动订单数的查询与缓存均按当前店铺计算，不继承另一店的数量。继承模式字段不可编辑，服务端忽略伪造字段并阻止直接元数据覆盖；覆盖选择沿用 `_gsm_overrides` 的presentation项。

muti-storefront-plugin 0.5.8、product-addon-plugin 3.8.4；单店插件保留原有基本行为，多店规则由 ProductExperience 适配层施加。原生编辑和经典加购为当前支持入口，Store API购物车读取／变更已有项经过相同重算；不宣称新增区块加购选择器或第三方编辑器兼容。

本轮开始只读盘点为72公共＋72品牌版本，已有展示及加购元数据均为0；没有自动改写这些业务商品、建立版本或设置营销规则。29项运行、5项订单统计和23项真实HTTP检查，以及浏览器实际覆盖保存／恢复继承通过；合成资料清理与原商品／元数据／品牌设置快照核对见 `qa/group-shop-manager/v058-local/LOCAL-v058.md`。仅本地，未连接或发布生产。


## 搜索引擎与跨店链接（0.5.9，本地）

每店只公开自己的销售商品、页面、文章与私有集合；公共商品不会成为前台销售页。相同商品／页面路径在不同域名下指向各自资料，直接使用外店或公共商品ID返回404，不能用gsm_brand参数切店。有效本店历史文章slug仍可301，其他店旧slug不跳转。分类名称、描述、标签及素材共用，但商品／评论数量和聚合数据按当前店计算。

启用收录后使用本店/wp-sitemap.xml；商品、页面、文章和分类URL均属于本域名，分类Sitemap只列本店有商品的分类及祖先，不生成作者Sitemap。停用收录时Sitemap不可用属于正常行为；noindex只控制收录，不替代资源访问校验。

菜单只使用本店资源。正文、摘要、商品短描述若留有另一注册店铺的业务链接或iframe，前台移除其href／src，不自动跳到另一店，也不修改编辑器中保存的原文；外店oEmbed不加载。图片、CSS、JS及其他wp-content素材可继续来自共用域名。

当前验收基于原生WordPress／Woo与本项目主题。安装第三方SEO、搜索、页面编辑器或自定义接口后，需重新运行SEO隔离套件；不能把本次原生入口通过等同任意插件已自动兼容。

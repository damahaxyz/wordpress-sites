# Group Shop 工作约定

## 新对话先读
1. `plugin/group-shop-manager/README.md`
2. `plugin/group-shop-manager/docs/HANDOFF.md`
3. `plugin/group-shop-manager/docs/ARCHITECTURE.md`
4. `plugin/group-shop-manager/CHANGELOG.md`
5. 涉及部署时再读根目录 `DEPLOYMENT.md` 和插件 `docs/OPERATIONS.md`。

根目录 `PROJECT-HANDOFF.md` 是复制来的 Trovesia 历史资料，不是 Group Shop Manager 的当前规格。

## 文档与开发必须同步
任何功能、数据结构、配置、权限、限制、部署流程或兼容性变化，必须在同一轮更新相应文档、CHANGELOG 和 HANDOFF 的当前状态/测试/后续事项。不得将计划写成已实现，不得将本地实现写成已上线。完成一次部署后记录真实版本、备份位置、检查结果及回滚方法。复杂修改先阅读最接近修改范围的实现与验收测试。

## 当前已确认产品决策
- **最新发布约束（2026-11-03）：后续改动只在本地测试；等用户明确通知再发布线上。旧的“验证后部署”授权已被本条覆盖，不能自动部署或在线执行分类清理。**
- group-shop 现有订单、用户等是测试数据，可按开发需要调整；部署前仍备份。
- 2026-11-04 用户最新决定（0.4.0，本地）：顾客每店独立原生用户，可在不同店复用可见用户名和真实邮箱；密码、默认地址和会话独立。Administrator／Shop Manager 为独立共享员工身份，由网络超级管理员按店授权，无自动 SSO。顾客角色固定 Customer，不能转换为员工。覆盖历史共享顾客账户／地址及登录自动加入店铺的决定。
- 商品内容、价格、排序、发布状态、评论与前台订单按店隔离。2026-11-03 最新决定覆盖原独立分类方案：分类与标签只有主站原生产品后台一份权威数据，增删改全站生效；分店仅有 WooCommerce 原生投影，无覆盖或独立编辑。主商品分类归属同步到已关联版本。商品集合继续按店保存。0.3.6 客户改用原生网络用户列表，0.3.4 订单改用所属店原生后台，不再提供中央汇总。
- 0.2.0 按用户最新决定移除批量库存：所有店铺的商品与变体不管理数量、始终有货。升级要通过 CRUD 迁移既有元数据及 lookup，不能只改前台显示；草稿和发布状态不变。
- 支付服务商未定，支付通道、共享付款方式、退款集成暂不开发。
- 不修改 FluentSMTP 核心，不承诺 Google 无法识别关联，不做针对搜索引擎的不同展示。
- 最新设计方向：能复用原生后台的商品、分类、评论、用户、订单等功能优先扩展字段/列/筛选/批量操作，不重复实现编辑器；插件聚焦店铺差异数据、主题读取约定和跨店协调。差异按店铺归属，换主题保留数据。逐项规划见插件 docs/NATIVE-ADMIN-REFACTOR.md，尚未实施，不得视为已上线。
- 店铺设置已先在 0.2.1 使用原生媒体选择 Logo，并直接读写原生 blog_public 收录设置；升级保留现有状态。媒体按店授权，不能在其他后台初始化处理前改变店铺上下文。整体原生后台收缩仍为规划。

- 0.3.0 历史本地版本曾采用独立分类（该方向已由 0.3.1 覆盖）：删除统一/店铺分类入口和旧处理器，迁移旧集合条件为本店 ID 后清除 _gsm_template_id/_gsm_template_store/_gsm_overrides。没有独立分类表可删除；保留核心表、原生分类/标签/图片/商品关联及商品发布映射。新店不继承分类，商品发布不覆盖分类标签。

## 代码边界
所有新功能位于 `plugin/group-shop-manager/`。使用 WordPress Multisite 原生用户与店铺隔离，不共享数据库表来连接独立 WordPress 安装。WooCommerce 数据使用 CRUD API 并兼容 HPOS。跨店访问必须恢复原上下文；只允许网络管理员执行中央管理写操作。不得记录密码、令牌、邮件正文、完整客户资料或 SMTP 凭据。删除/停用插件默认保留业务数据。禁止顺带修改 trovesia-shop 目录或其他线上店铺。

- 0.3.1 本地待发布：店铺商品增加主图、列表快捷上架/草稿禁用，移除库存列与分类/标签编辑；使用原生富文本和按店授权媒体，同页每次最多 20 个变体。SharedTaxonomies 管理唯一主站原生分类/标签权威，保持各店原生 ID 投影与集合兼容；迁移先汇集各店独有分类，slug 冲突主站为准，默认分类归一，集合不升为共享分类。新要求已授权这些本地数据转换，不部署线上。

- 0.3.2 本地待发布：商品集合为列表／独立编辑页／可恢复回收站；标题、描述、本店媒体封面，无 slug／父级输入。系统自动内部地址，旧 URL 保留。规则按统一分类／标签或本店手选，搜索名称／编号每次 25 条。首页／专题用原生集合区块或短代码，经典 Shop 可选集合与属性／价格叠加；集合仍按店独立，不自动替换主题写死模块。仅本地，未获新授权不得上线。

- 0.3.3 本地：原生分类／标签列表和编辑页补只读类型及归属。共享词表显示全站共享，集合归属取当前 blog_id，不按 term ID 跨店推断；原生页非全网汇总，其他店经中央集合切换。无迁移或权限变化。

- 2026-11-04 本地 QA 已按用户最终确认使用 HTTP 的 www.main.local、www.branda.local、www.brandb.local、www.brandc.local、www.brande.local、www.brandf.local、www.brandg.local，blog_id 为 1／6／7／9／11／12／13；原 localhost 分店路径已退休。精确 Apache 转发与容器内部 DNS、媒体原生 URL 已配好，系统代理没有改动。旧严格 localhost 的安装器／fixture／验收不可直接运行或去掉保护；当前域名只读验收 check-local-domains.py。启动、备份及回退见最新 OPERATIONS／HANDOFF。

- 0.3.4 本地：用户决定移除统一订单页，使用所属店原生 Woo 订单管理；概览按目标店 HPOS／传统存储生成入口。保留来源与顾客归属保护，不恢复中央状态／备注处理器或全店汇总。QA 验收后域名被外部改为 www.main.com 等，未回改；原 localhost 脚本须先确认本地隔离前提，不能误访问公网同名站。

- 0.3.5 本地：删除独立评论页及 review_status，原生产品 Reviews 仅增加只读所属店铺列（店名＋当前 blog_id），评论和回复均支持；不聚合、迁移或共享评论，不加 commentmeta，不改原生权限及普通评论页。QA 当前已为 www.main.local 等 .local 域名，宿主 loopback，保留既有映射，不能使用旧 localhost 路径或公网同名站误验收。

- 0.3.6 本地：删除共享客户页，原生网络用户仅补只读首次来源店铺，复用 Sites 当前成员关系，不把历史 joined_at 当现成员；无用户迁移或新元数据。保留 Customers 登录、角色保护、共享地址、密码范围提示和会话撤销。来源读取必须同网络、恢复上下文且不可用时保留编号；新列不扩展各店用户页，不扩大权限。

- 0.3.7 本地：用户明确移除主商品发布标签及功能，跨店复制／覆盖／媒体导入／新发布映射 API 已删除，不得按旧规划移至原生面板或为测试恢复。保留本店编辑、上下架、已有商品／变体／附件／来源元数据／历史映射与审计，旧映射仅继续服务既有分类归属同步。无数据清理迁移；旧依赖 Catalog::publish 的 fixture 套件不可直接执行，当前退休验证使用 retired-publisher.php、catalog-state.php 和 check-retired-publisher-local.py。仍只本地，未获新通知不发布。

- 0.4.0 本地已实施用户隔离：Identities 维护原生用户的类型／店铺／可见用户名和邮箱索引，顾客真实邮箱仍写 wp_users；内部用户名唯一。Customers 覆盖登录、Cookie、重置、角色、REST 与注册；UserAdmin 复用原生网络用户创建员工及按店授权面板；IdentityPrivacy 适配原生按邮箱导出／擦除；UserMigration 只能显式运行，先备份与预检，绝不在访问页面／激活时自动拆分。既有本地共享顾客已拆分，订单／评论／购物车／下载／令牌按所属店重绑。旧全局 get_user_by(email) 有歧义，第三方集成须使用本店解析，不承诺任意插件自动兼容。回滚须成套数据库与源码；仍未获生产发布授权。历史 0.3.6 的共享行为及仅网络列限制已被本次决定覆盖。

日期：2026-11-04，Asia/Taipei。仅本地；未连接或部署生产，线上版本仍沿用历史 0.2.2 记录。

“统一订单”标签及其聚合列表、自建详情、备注／有限状态写操作移除。概览“原生订单”按所属店 HPOS／传统存储生成正确入口。现有订单、备注、审计、来源快照、前台归属保护和已有 HPOS 来源列保留。原生列表只显示当前店，没有全网络同屏汇总或自动 SSO；原生权限、状态、通知和网关配置接管操作。

- 三个改动 PHP 文件语法检查通过。
- [31 项集成](native-orders.json)通过：主店 HPOS、Brand A/B 传统订单模式，原生创建来源快照、原生 CRUD 状态／内部备注、两种链接分支、顾客来源校验、概览入口与旧标签回退。仅创建本地合成订单 #60（主店）、#138（Brand A）、#40（Brand B），未导入生产资料；合成临时权限测试用户已删除。

- 内置浏览器确认概览为九个标签，“统一订单”消失，各店有原生订单链接。分店浏览器跳转未完成验收，原因见下节。没有声称本轮重跑集合／商品等旧版全量套件。

## 验收期间的外部环境变更

初次成功检查之后，内置浏览器进入原 /brand-a/ 后台出现找不到站点，再跳转 www.main.com；原 localhost HTTP 套件重跑也在登录／版本断言终止。随后 WP-CLI 只读核对确认 QA 主店 domain/home/siteurl 已改为 www.main.com，Brand A/B 为 www.branda.com／www.brandb.com，其他站也映射新域名；这些变更不在本轮代码／测试脚本内，未恢复或覆盖。

因此 60 项通过代表域名变更前的合成网络状态，不能声称新域名环境的浏览器／HTTP 验收已通过。原 localhost:18087 脚本须先确认本地隔离配置才能重跑，不得直接访问公网同名域名。当前成功报告保留历史结果，HTTP 报告曾被失败重跑的 shell stdout 重定向清空，已按工具捕获的原始成功输出恢复，并在 JSON 中标记；脚本现仅在完成后写报告，后续失败不覆盖成功记录。未保存可交付的新截图。

后续在稳定且明确隔离的本地域名环境核对原生跳转。仍需用户明确新通知才可发布；本次没有线上操作、分类清理或订单迁移。
